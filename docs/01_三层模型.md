# 01 · 三层模型

> 整个方法论的骨架。别的都可以变，这三层不变。

---

## 为什么是三层

一张电商成品图，从「能不能改」的角度看，只由三种东西组成：

1. **像素**（照片、产品图、背景）—— 不需要「重建」，原样搬过去就行
2. **几何**（色块、表格线、标注线、按钮）—— 是**参数**，不是像素
3. **文字**（标题、正文、参数、价格、活动）—— 是**内容**，必须能改

把这三类混在一起处理，就只有一个结果：**改不动**。

所以拆成三层，每层用**最适合它的技术**处理：

| 层 | 产物 | 技术 | 可编辑 |
|---|---|---|---|
| **L1 照片层** | `assets/plate.png` | 原图挖字 + 修补 | 换图可改 |
| **L2 矢量结构层** | SVG `<rect>` / `<line>` | 几何检测 + 参数化 | **改色/改宽 = 改一个数** |
| **L3 文字层** | SVG `<text>` | OCR + 寻优 | **活字，随便改** |

---

## L1 照片层

**做什么**：原图里把「要重建的文字」挖掉，剩下的原样留作底板。

**关键点：挖字掩膜用「文字自身 fill 色」，不用「与区域众数色差异大」。**
小区域里众数色会被文字本身带偏 → 把胶囊底 / 横幅底 / 价卡底一起挖掉 → 渲出来是白块。

**回填用「留出法」选算法**（inpaint vs 多项式拟合）：

- inpaint 适合纯色面板上的小字（周围均匀，直接补色）
- 多项式适合大号字压在渐变上（inpaint 会拖糊）
- 判据**不能**是「重建 vs 原图」—— 原图那格是**字**不是背景，越像字越"准"，是自欺欺人
- **留出法**：在元素附近随机挑一批**已知是背景**的像素，假装它们也被挖掉了，
  看两种算法谁能更准把它们还原出来，谁赢就派给真正的文字区
- **考题厚度要跟真实难度一致**：真实要补的是粗笔画的洞（大字笔画十几 px 宽），
  用单像素考 inpaint 等于送分

## L2 矢量结构层

电商图比海报多一层刚需：**背景结构**。

- 标题条 / 按钮 / 标签块（纯色矩形，可能压着白字）
- 参数表的表格线、尺寸标注线（1~2px 细线）

这两类如果不抽成矢量，文字挖掉后背景回填会把它拖糊，整张图的结构感就塌了。
抽成矢量后 → 改色值、改宽度、改线型都是改一个数，不用重画。

**检测判据（按可靠性排序）**：

1. **直边矩形** —— bbox 填充率 ≥ 0.93。产品灯面那种「平坦但形状是椭圆」的
   区域填充率只有 0.78，标题条这种真色块是 1.00 —— 这一条比任何边缘算子都可靠。
2. **色彩离散度低** —— 不用边缘算子：边缘算子会被 JPEG 白字振铃骗
   （色块上压字 → 边缘密度高 → 真色块反被误杀）。
3. ⚠ **取色必须用原始 bin 像素**，不能用形态学闭运算后的掩膜 ——
   闭运算会把色块上的白字笔画桥接进来（9×9 核足以跨过 3~6px 宽的字），
   于是白字被算进色块，色彩离散度从 4 飙到 39，真色块反被误杀。

## L3 文字层

**为什么必须是活字 SVG，不是图片**：

- 要能改价、改活动、改参数 → 必须能选中、能改
- 要能锁字宽 → `textLength` + `lengthAdjust="spacingAndGlyphs"`
- `y` 必须是**基线**不是顶边，否则字号一变就跳

**字体是族级配方属性，必须能由调用方指定。**
「海报」场景的启发式（大字中文 → 宋体）在电商图上错得离谱：
淘宝促销大字是**黑体**，套成宋体后重建出来是「细瘦宋体」，差异率能飙到 20%。

## 三层的接口：spec.json

三层在 `spec.json` 里各占一段：

```jsonc
{
  "key": "demo_param_card",
  "src": "examples/samples/demo_param_card.png",
  "crop": [0, 0, 0, 0],

  "text": [                       // L3
    { "id": "t00", "text": "24W", "box": [..],
      "base": 244, "size": 28, "weight": 700,
      "fill": "#221E2C", "font": "Noto Sans SC",
      "x": 464, "text_length": 72, "tol": 45 }
  ],

  "rects": [                      // L2
    { "id": "bar", "box": [0, 0, 900, 108], "fill": "#1A162C", "rx": 0, "opacity": 1.0 }
  ],

  "lines": [                      // L2
    { "id": "ln0", "x1": 40, "y1": 692, "x2": 520, "y2": 692, "stroke": "#D0C4B4", "w": 1 }
  ],

  "art": [                        // L1 里的美术素材，原样裁切原位贴回
    ["blk00", [345, 913, 638, 1000]]
  ],

  "sweep": [                      // 寻优记录（可复现）
    { "marker": "24W", "attr": "font-size", "values": [25, 28, 31], "region": [..] }
  ]
}
```

**spec 就是配方。** 换同族图时改 spec 里的参数；出新品时复制 spec 改内容。
引擎不改。

## 分层正确性的硬校验

**非文字区差异率必须为 `0.00%`** —— 排除所有文字元素框之后的差异。

不为 0 → 「哪些是素材、哪些是文字」判断错了。
先查分层，再谈像素：这个数不为 0 的时候，调寻优参数是浪费时间。
