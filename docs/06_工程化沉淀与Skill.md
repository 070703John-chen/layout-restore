## 一、三个资产的分工

之前的东西散在两个地方（本地工程 + 引擎），现在分成三块，各有明确边界：

| 资产 | 位置 | 是什么 | 给谁用 |
|---|---|---|---|
| **开源仓库** `layout-restore` | GitHub `070703John-chen/layout-restore` | **通用引擎 + CLI**。不含任何第三方素材、不含项目私有路径 | 招聘方 / 任何人 clone 就能跑 |
| **Skill** `layout-restore` | agent 的 skill 目录（`~/.mavis/agents/<agent>/skills/layout-restore/`） | **批量流水线的说明书 + 编排脚本**（选片/跑批/验收/报告/建站）。装在 agent 上，任何 session 都能触发 | 我（agent）在任何 session 里接到「复刻这批图」就能直接干 |
| **本地工程** `15_淘宝复刻工程` | 本机工作台目录（路径见 `config.local.yaml` 的 `paths.project`） | **数据与产物**：原图库、族聚类、50 张交付包、指标 | 陈的工作台 |

### 依赖方向（单向，不循环）

```
本地工程（数据/产物）  ──数据──▶  Skill（编排）  ──调用──▶  开源仓库（引擎+CLI）
        ▲                                                 │
        └────────────────── 产物写回 ──────────────────────┘
```

**Skill 不含引擎代码**，它只编排；**开源仓库不含项目数据**，它是通用件。
这样任何一个坏了都不影响另一个。

### 版本同步规则

| 方向 | 谁是 source of truth | 怎么同步 |
|---|---|---|
| Skill → 仓库 | **仓库** `layout-restore/skills/layout-restore/` | 改完仓库里的那份，复制到 agent skill 目录 |
| 仓库 → 本地工程 | 各自独立 | 本地工程的数据/产物不入库 |

> 2026-10-29 踩过：构建脚本把「上一版产物」当模板反向覆盖，改了模板却不生效。
> **所以：仓库那份是唯一真相源，agent skill 目录是部署产物。**

## 二、Skill 是什么、不是什么

| | 说明 |
|---|---|
| **是什么** | 一份「说明书 + 脚本包」。说明书告诉 agent 什么时候用、怎么用、遇到坑怎么办；脚本负责确定性的本地计算 |
| **不是什么** | 不是程序本体。真正的引擎在开源仓库里，skill 只编排 |
| **触发方式** | 用户说「复刻这批图 / 批量还原 / 还原成可编辑源件包 / 复刻一下原图」 |
| **不触发** | 「裁个图 / 改尺寸」→ 用图像库；「原创画图」→ 用生图工具；「帮我抓电商素材」→ 不做（版权） |

### 结构

```
skills/layout-restore/
├─ SKILL.md              说明书（108 行，lint 通过）
├─ config.yaml           唯一配置（路径/阈值/选片策略/达标口径）
├─ scripts/
│  ├─ doctor.py          环境自检（跑之前先跑它）
│  ├─ pick.py            选片（版式簇配额 + 最远点采样）
│  ├─ run_batch.py       批量复刻（并行 + 日志落文件 + 断点续跑）
│  ├─ verify_all.py      全量验收（从交付包重渲对账）
│  ├─ report.py          指标 + 三条口径达标率
│  ├─ make_site.py       对比网站
│  ├─ pipeline.py        一键全流程
│  ├─ common.py          共享层（配置/路径/环境/指标）
│  └─ site_template.html 对比站模板
└─ references/
   ├─ 铁律.md             15 条硬规则（最有价值）
   ├─ 三层模型与版式族.md  分层骨架 + 族怎么定怎么复用
   └─ 环境与依赖.md       依赖/脚本分工/产物落点/时间成本
```

### 顺带修掉的两个真 bug

1. **config.yaml 解析失败却静默用默认值**
   我把 Python 的 `# -*- coding -*-` + docstring 头写进了 YAML 文件头 →
   YAML 报 `expected '<document start>'` → `common.load_cfg()` 打印一句就**退回默认值** →
   doctor 照样报「可以跑」，但所有路径其实都是默认值。
   修法：① 配置开头改成纯 YAML 注释 ② **解析失败直接退出**，不静默降级
   （坏配置静默降级比崩掉更糟：脚本拿着默认路径跑，看起来在正常跑但全跑错地方）

2. **skill 目录里放了空 `assets/`** —— 反模式 #1，skill 是给模型读的，不是给人看的产品文档。

## 六、这次沉淀下来的元规律

做 skill 本身也是一次「还原」：

| 还原类比 | skill 类比 |
|---|---|
| 三层模型 | skill = 说明书（模型读）+ 脚本（确定性计算）+ references（ bulky 背景） |
| 达标率 | lint + eval = skill 的验收指标 |
| 规格说明.md | SKILL.md 是 skill 的「唯一编辑入口」 |
| 像素层降级 | eval 暴露弱点就改，不硬撑 |

> **最重要的两条**：
> 1. **坏配置要崩，不要静默降级** —— 否则你会在错的路径上跑完一整轮才发现。
> 2. **「怎么判」和「判什么」分开** —— skill 里也一样：脚本管怎么判，config.yaml 管判什么。
