# 03 · 版式族方法论

> 「批量复刻」的正确形态是什么？这一篇给答案。

---

## 1. 族 = 一套版式，不是「长得像的一堆图」

**版式族 = 离散可命名的结构单元**。

例：`深色标题条 + 参数表`、`大括号标题 + 圆形标注`、`对比双栏`、`三步骤并排`……
每个族有**固定的图层结构**（几个色块、几条线、几组文字、什么位置关系）。

### ⚠ 自动聚类不能用来定义族

实测：对 121 张淘宝图抽 12 维特征做 KMeans，聚出来的是
**视觉明暗 / 密度**的分组（「亮图」「暗图」「花图」），**不是版式结构**。

自动聚类只能当**审校批次**（同一批图放一起看），**族必须人工定**。

---

## 2. 族提供「判据与参数」，不提供「像素坐标」

**实测结论：同族复用时，直接复制上一张的坐标必然错位。**

同族的不同图，结构相同但每个元素的位置都不同。
复制坐标 → 文字压在错误的位置上 → 重建出来是废图。

所以族的正确用法：

| 族提供 | 族不提供 |
|---|---|
| 图层结构（有几层、每层是什么类型） | 像素坐标 |
| 判据（什么算标题条、什么算参数行） | 具体数值 |
| 参数（字号档位、字重档位、间距比例） | 具体色值 |
| 字体选择 | |

**每一张图都要各自自动拆一遍。** 族让「拆」这件事**快且稳**，不是让它**免拆**。

---

## 3. 拆解的产物是「族级配方」

```
探针 → spec 草稿 → 人工审一遍 → spec（= 族配方 + 这张图的标定结果）
```

审校只做三件事：

1. **文字框有没有把素材误判成文字**（反之亦然）
2. **字色是否取反**（探针会给出告警列表）
3. **美术素材框是否需要手动收紧**（探针的色块检测和文字框重叠时会漏）

「量坐标、色值、字号」这八成工作量已经被自动化掉了，人只做**审**不做**量**。

---

## 4. 标定结果要落盘，才能复现

寻优会把字号 / 基线 / x / 字重 / 字色**回写进 spec**。
所以 `spec.json` 既是**输入**也是**输出**：

- 重新渲染同样的图 → 直接用标定后的 spec，不用重跑寻优
- 想换一张同族图 → 用标定前的 spec 当起点

⚠ 回写必须用**原文 marker**，匹配时统一转义一次 —— 见 [02_铁律.md](02_铁律.md) 第 6 条。

---

## 5. 批量复刻 ≠ 批量渲染

「渲染」很便宜（一次几百毫秒），**「拆解」才是瓶颈**。

所以批量能力要建在**拆解**上：

```
一张图 → 自动拆 → 审 → 标定 → spec
N 张图 → N 份 spec → 批量渲染 + 批量验收
```

而**不是**：一张图拆一次，然后套到 N 张图上（那是编造）。

---

## 6. 新族怎么加

1. 人工定族名 + 画出版式结构草图
2. 找 2~3 张同族参考图
3. 跑 `build`，看拆解结果对不对
4. 不对的地方 → 改**判据**（`probe_layers.py`）或改 spec 草稿规则（`autospec.py`），
   **不要**去改渲染引擎
5. 沉淀成族配方：spec + 字体 + 判据组合

### 「族」和「通用视觉引擎」的取舍

**体系化模板标定 + 自动套用，不是通用视觉引擎。**

同一套阈值跨 3 个版式体系必翻车 —— 这是实测结论。
所以：**按族拆，每族的图层结构固定可复用**。
这才是能复现、能交付、能写进作品集的「工程」。
