# 三层模型 · 版式族方法论

> 两个问题：一张图怎么拆成可编辑的层？拆完之后怎么变成**可复用的族**？

---

## 一、三层模型

一张电商成品图，从「能不能改」的角度看，只有三种东西：

1. **像素**（照片、产品图、背景）—— 不需要重建，原样搬过去
2. **几何**（色块、表格线、标注线、按钮）—— 是**参数**，不是像素
3. **文字**（标题、正文、参数、价格、活动）—— 是**内容**，必须能改

混在一起处理，就只有一个结果：**改不动**。

| 层 | 产物 | 技术 | 可编辑 |
|---|---|---|---|
| L1 照片层 | `assets/plate.png` | 原图挖字 + 修补 | 换图可改 |
| L2 矢量结构层 | SVG `<rect>` / `<line>` | 几何检测 + 参数化 | **改色/改宽 = 改一个数** |
| L3 文字层 | SVG `<text>` | OCR + 寻优 | **活字**，能改价改文案 |

### 三层的接口：`spec.json`

```jsonc
{
  "key": "M04",
  "src": "...", "crop": [0,0,0,0],
  "text":  [ { "id":"t00", "text":"一级能效", "box":[..],
               "base":244, "size":52, "weight":300,
               "fill":"#FFFDF8", "font":"Noto Sans SC",
               "x":110, "text_length":499, "tol":45 } ],
  "rects": [ { "id":"r00", "box":[0,0,900,108], "fill":"#1A162C", "rx":0, "opacity":1.0 } ],
  "lines": [ { "id":"l00", "x1":40, "y1":692, "x2":520, "y2":692, "stroke":"#D0C4B4", "w":1 } ],
  "art":   [ ["blk00", [345,913,638,1000]] ],
  "sweep": [ { "marker":"一级能效", "attr":"font-size", "values":[49,52,55], "region":[..] } ]
}
```

**spec 就是配方**：换同族图改 spec 里的参数；出新品复制 spec 改内容。**引擎不改。**

### 分层正确性的硬校验

**非文字区差异率必须为 `0.00%`** —— 排除所有文字元素框之后的差异。
不为 0 → 「哪些是素材、哪些是文字」判断错了。
先查分层，再谈像素：这个数不为 0 的时候，调寻优参数是浪费时间。

### 双版本

| 版本 | 文字 | 改文案 | 像素一致度 |
|---|---|---|---|
| 活字版 `index.html` | 真 SVG `<text>` | ✅ | 取决于字体是否可得 |
| 像素层版 `index_px.html` | 原图裁切的字形图 | ❌ | ✅ 逐像素一致 |

**字体替代是这个方法的天花板**，不是分层逻辑的问题。
把主视觉换成原图裁切块后残差能掉到 0.4% —— 说明分层本身是干净的。

## 二、版式族

### 族 = 离散可命名的结构单元

例：`深色标题条 + 参数表`、`大括号标题 + 圆形标注`、`对比双栏`、`三步骤并排`……
每个族有固定的图层结构（几个色块、几条线、几组文字、什么位置关系）。

### ⚠ 自动聚类不能用来定义族

实测：对 121 张图抽 12 维特征做 KMeans，聚出来的是**视觉明暗 / 密度**的分组
（「亮图」「暗图」「花图」），**不是版式结构**。

自动聚类只能当**审校批次**（同一批图放一起看），**族必须人工定**。

### 族提供「判据与参数」，不提供「像素坐标」

**实测：同族复用时，直接复制上一张的坐标必然错位。**
同族不同图结构相同但每个元素位置都不同 → 复制坐标 → 文字压在错误位置 → 重建出来是废图。

| 族提供 | 族不提供 |
|---|---|
| 图层结构（有几层、每层什么类型） | 像素坐标 |
| 判据（什么算标题条、什么算参数行） | 具体数值 |
| 参数（字号档位、字重档位、间距比例） | 具体色值 |

**每一张图都要各自自动拆一遍。** 族让「拆」这件事**快且稳**，不是让它**免拆**。

### 新族怎么加

1. 人工定族名 + 画版式结构草图
2. 找 2~3 张同族参考图
3. 跑 `build`，看拆解结果对不对
4. 不对的地方改**判据**（`probe_layers.py`）或 spec 草稿规则（`autospec.py`），
   **不要**去改渲染引擎
5. 沉淀成族配方：spec + 字体 + 判据组合

### 「族」vs「通用视觉引擎」

**体系化模板标定 + 自动套用，不是通用视觉引擎。**
同一套阈值跨 3 个版式体系必翻车 —— 这是实测结论。
所以：**按族拆，每族的图层结构固定可复用**。

## 三、批量化的正确形态

「渲染」很便宜（一次几百毫秒），**「拆解」才是瓶颈**。

```
一张图 → 自动拆 → 审 → 标定 → spec
N 张图 → N 份 spec → 批量渲染 + 批量验收
```

**不是**：一张图拆一次，然后套到 N 张图上（那是编造）。
