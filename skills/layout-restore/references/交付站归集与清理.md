# 交付站归集 · 分类 · 清理归档（方法论）

> 这份文件是「跑批跑完之后，怎么把产物变成一个网站 + 一个存放目录」，
> 以及「怎么安全地删掉旧站点、归档没用的东西」的完整做法。
> 对应铁律 85–93。

---

## 一、为什么要归集

批量跑批的产物会天然散落在很多地方：`out/<KEY>/`、`out_opt/<KEY>/`、
`runs/`、`_work/longimg_batch/`、各种「对比站」目录……
用户拿到手是一堆文件夹，看不出「我到底做了什么」。

⇒ 目标形态：**一个网站 + 一个存放目录**。

```
交付站\
├── index.html            ← 唯一网站（双击即开，离线可用）
├── data\index.json       ← 结构化索引（每条：分类 / 差异率 / 各版本图路径）
├── assets\<产品组>\{main,sec,long}\
│                          ← 全部产物图（唯一存放处）
└── src\<产品组>\<KEY>\    ← 可编辑源件包（index.html = 唯一编辑入口）
```

★ **专科页面用 `../assets/` 相对路径**引用同一套图 ⇒ 增删品类不重复拷贝，
且「一个存放目录」不被破坏。

## 二、归集流程（按顺序，缺一步就返工）

| 步 | 做什么 | 为什么这个顺序 |
|---|---|---|
| 0 | **先把多批次合并成同一份产品表** | 一个批次一个站 = 「散落」。产品表（`jobs.json`）是分类的唯一依据，必须先合 |
| 1 | 产物图 → `assets/<产品组>/<图位>/` | 产品组目录名要和产品表一致，否则分类会散 |
| 2 | 源件包 → `src/<产品组>/<KEY>/` | 源件包是交付物的「可编辑」部分，必须和图放在一起 |
| 3 | **字体共享 + NTFS 硬链接** | 每个 key 的 `assets/` 都塞 3 个字体（全库 md5 相同），226 个 key 就重复 6.3 GB ⇒ 共享一份 `_fonts/` + `os.link` 落回各包 `assets/`，**43 MB 解决 6.3 GB**，源件包相对路径零改写 |
| 4 | 生成 `index.html` + `data/index.json` | 页面从索引生成，索引是唯一数据源 |
| 5 | **Playwright 验收** | 坏图 / 磁盘缺文件 / 横向溢出 / 分类计数 / 灯箱点测 |
| 6 | **源件包自洽体检** | 708 个 HTML、9538 个资源引用，**断链必须为 0**（HTML 引用的每个 asset 都要真实存在） |
| 7 | 清理旧站点（见第五节） | 归集完再清，否则会删掉还没归集进去的东西 |

★ 步骤 3 的字体硬链接是**磁盘大头**：`交付站` 朴素求和 13.4 GB，真实占用 1.87 GB。

## 三、分类维度

1. **品类**（6 个：手机 / 香水 / 品牌香水 / 零食 / 电煮锅 / LED灯）
2. **产品**（47 个产品组：`tb22_*` = 平台直采，`alt_*` = 多品类）
3. **图位**（主图 / 附图 / 附图2 / 附图3 / 附图4 / 详情长图）

★ **第一维度必须是「产品归属」** —— 用户要对比的东西属于同一商品 ⇒ 同一产品必须在一处。
版式族只能作为**组内排序**的可切换项，不能当第一维度。

★ **专科页面（单品类）可以反过来按图位分组**，但要同时提供「按产品」视图：

| 视图 | 一级分组 | 二级分组 |
|---|---|---|
| **按图位**（默认） | 主图 / 附图 / 附图2 / 附图3 / 附图4 | 产品组 |
| **按产品** | 13 个产品组 | — |

「分主图附图」和「同产品在一处」两个需求不冲突，两个视图都留着即可。

★ **详情长图 ≠ 平台商品详情页**（来自导购/媒体站）⇒ 单列一类、标注来源、
像素层与活字层 md5 相同时只列两列、超高纵向图内联必须 `max-height` + 灯箱。

## 四、交付页硬规则

- **不做拼图**：每张一行，原图 | 生成图 **并排**
- **图片按真实宽高比**显示，**禁 `aspect-ratio:1/1`**（会把竖图压方、看不出差别）
- **采集图与生成图放同一个页面**（用户 2026-11-09 明确要求），不要拆两个站
- 灯箱 100% 逐像素，**左右键在采集图 ↔ 生成图之间切换**
- 非目标内容（详情长图等）**折叠在末尾**，页头开关展开
- 数字全实算，不留会失效的链接

### 验收清单（交付前必查）

| 检查 | 怎么查 |
|---|---|
| 坏图 | 只判**可见图**（`offsetParent !== null`）；折叠项展开后再单独验一遍 |
| 磁盘缺文件 | 用 `i.src`（解析后的绝对 URL）反解路径，**不能用 `getAttribute('src')`** 的相对路径 |
| 横向溢出 | `scrollWidth - clientWidth === 0` |
| 分类计数 | 数**各分组的条目数**（`{主图:13, 附图:12, ...}`），只数总数看不出渲染中断 |
| 灯箱 | 点图 → `#lb` 有 `on` 且 src 反解后文件存在 |
| 源件包 | HTML 引用的每个 asset 都存在（断链 = 0） |
| 分组完整性 | 各分组条目数之和 == 总条目数 |

★ 等待图片加载**必须加超时**且**只等可见图** —— 被折叠的 lazy 图永远不触发 `load`，
无超时的 `Promise.all` 会死等（实测挂住一整轮验收）。

## 五、清理与归档

### 5.1 先分清三种东西

| 类别 | 判据 | 动作 |
|---|---|---|
| **重复** | 内容已被归集站完整覆盖（逐文件 md5 自证） | 删 |
| **独立成果** | 归集站覆盖度 < 100%（实测三个旧站 100 条只覆盖 2 条） | **归档，不能删** |
| **过程证据** | 状态板 / 试点报告 / 差异热力图 | 归档 |

★ **「看起来是老站、看着像冗余」不是删除理由。**
删之前必须逐条证明「归集站里确实有它」，有缺口就 SKIP。

### 5.2 逐文件自证覆盖（删除判据）

| # | 判据 | 可否删 |
|---|---|---|
| ① | 目标站有 **同名 + 同尺寸 + 同 md5** 的副本 | ✅ |
| ② | 已知中间产物（`_patch_sweep.*` / `_render_*.png` / `_diag*/`） | ✅ |
| ③ | 被淘汰的旧版本 KEY（同图有重做版入选） | ⚠ 先归档 `_spec.json`/`_report.json`/`index*.html` 再删 |
| ④ | 目标站无副本，但目标站该 KEY 的 HTML 不按相对路径引用它 | ✅ 冗余资产 |
| ⑤ | 以上都不是 | 🚫 **阻塞，ABORT** |

可执行脚本：**`scripts/audit_coverage.py`**（本 skill 自带）。

★ **两个真会翻车的索引坑**：

- 建索引时 `len(rel) >= 3` 会把 `<slug>/<KEY>/index.html` 这类**顶层文件全漏掉**
  （它们 rel 长度是 2）⇒ 必须 `>= 2`。
- 判「HTML 是否引用某资产」按 **basename** 匹配 ⇒ 会把 `_diag2/assets/blk00.png`
  误当成被引用的 `assets/blk00.png` ⇒ 必须按**相对 KEY 目录的路径**匹配。

### 5.3 归档长什么样

```
_归档\
├── 早期三站_20261109\      ← 独立批次成果（覆盖度不足的）+ _说明.md 写清「为什么归档」
├── 族谱系_20261109\        ← 拼图与状态板（派生视图 + 过程证据）
└── 旧版本KEY_20261109\     ← 被淘汰 KEY 的可重建小文件
```

★ 每份归档都要带 `_说明.md`，写清：**内容是什么 / 为什么不能删 / 各自的源件包在哪**。

### 5.4 磁盘账

- **按 inode 去重统计**（`os.lstat().st_ino` 去重），否则硬链接被重复计数
  （实测朴素求和 32.4 GB vs 真实 20.5 GB）
- 真实释放量与 `Get-PSDrive` 的可用空间变化对得上才算数

### 5.5 清理后必须给生成脚本加闸门

删掉 `out/` 这类**被脚本当输入源**的目录后，
任何一次「重跑一下出站脚本」都会**把成品静默覆盖成空站**。

```python
if not os.path.isdir(OUT):
    print("[ABORT] 源目录 out/ 不存在（已清理）。未改动任何产物。")
    print("        正确顺序：① 跑引擎生成 out/ + out_opt/  →  ② 跑归集脚本  →  ③ 跑出站脚本")
    return 2
```

★ 验收：故意重跑，确认 `exit=2` **且成品文件字节数前后完全一致**。

## 六、模板生成的两个坑

1. **不要用 `str.format()` 填模板** —— CSS 里的 `{}` 会让它炸（`KeyError: '--bg'`）。
   用 `@@TOKEN@@` 占位符 + `str.replace()`，并在替换后断言没有残留占位符。
2. **Python 侧的常量必须显式注入 JS 侧** —— JS 里引用一个没注入的常量会
   `ReferenceError`，`render()` 在渲染完第一项后**静默中断**，
   页面表现为「内容少了一半」，很容易误判成数据源问题。

```python
subs = {'@@ROLES@@': json.dumps(ROLE_ORDER, ensure_ascii=False)}
page = TEMPLATE
for k, v in subs.items():
    page = page.replace(k, v)
for k in subs:
    assert k not in page, '未替换: ' + k
```
