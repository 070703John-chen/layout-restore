# 环境 · 依赖 · 脚本说明

> 这个 skill **不自带依赖**。它调用的是本机已经装好的 Python 工具链。
> 执行前先跑 `python scripts/doctor.py`，缺什么一目了然。

---

## 1. 依赖清单

| 东西 | 配置项 | 缺了会怎样 |
|---|---|---|
| Python（含 chromium） | `engine.python` | 出图全废（只有这个 python 装了 playwright 的 chromium） |
| 还原引擎 | `engine.restore` | 探针/渲染/寻优全废 |
| 工程脚本（`tb_run.py` 等） | `paths.project` | 批量跑不了 |
| 淘宝原图库 | `paths.raw` | 没图可复刻 |
| 族聚类产物 | `paths.features` / `paths.clusters` | 选片没法按簇配额 |
| 通用版 verify | `paths.verify` | 验收跑不了 |
| 成品交付根 | `paths.deliver` | 交付件没地方放 |

> **路径全部写在 `config.local.yaml`（不入库）**，仓库里的 `config.yaml` 是占位符。
> 本机真实路径写进 `config.local.yaml` 即可，`load_cfg()` 会自动叠加覆盖。

Python 包：`numpy` / `opencv-python` / `Pillow` / `playwright` / `PyYAML` / `rapidocr-onnxruntime`

## 2. 脚本分工

| 脚本 | 干什么 | 确定性？ |
|---|---|---|
| `doctor.py` | 环境自检：引擎/python/chromium/OCR/原图库/聚类产物逐项报 | ✅ 纯本地 |
| `pick.py` | 选片：按版式簇配额 + 簇内最远点采样 | ✅ 纯本地 |
| `run_batch.py` | 批量复刻：每张跑完整链（探针→spec→矢量→渲染寻优→像素层→交付） | ✅ 调引擎 |
| `verify_all.py` | 全量验收：从交付源件包重渲 + 和原图对账 | ✅ 纯本地 |
| `report.py` | 指标汇总 + 三条口径达标率 + 分簇分析 → Markdown | ✅ 纯本地 |
| `make_site.py` | 对比网站：原图｜还原图 横向并排的卡片 + 可放大灯箱 | ✅ 纯本地 |
| `audit_coverage.py` | **删除前闸门**：逐文件 md5 自证「已被归集站覆盖」，覆盖不了就阻塞不删 | ✅ 纯本地 |
| `diag_why.py` | 自动定性「这张为什么差」：分区复算 → 文字区差异 → 是不是字体不可得 | ✅ 纯本地 |
| `pipeline.py` | 一键串起上面全部 | ✅ 编排 |
| `site_template.html` | 对比站的 HTML 模板（`/*__DATA__*/[]` 是数据占位符） | 模板 |

**为什么是 Python 而不是 Node**：整条链路（OCR / 渲染 / 寻优）本来就是 Python，
脚本只是**编排层**。重写成 Node 只会多一层 shell 调用，没有任何收益。

## 7. 字体授权（开源必读）

仓库只随附 **SIL OFL 1.1** 的开源字体，且**必须随附许可全文**
（`layout_restore/assets/OFL-*.txt` + `THIRD_PARTY_NOTICES.md`）。

**商业字体（Century Gothic / Bodoni MT 等）一律不入库** ——
它们的授权写明「不得再分发」。需要更准的还原效果时，
把字体文件自己放到 `layout_restore/assets/` 或 `LAYOUT_RESTORE_FONTS` 指向的目录，
引擎会自动启用；没放就降级到仓库自带的开源字体。

## 8. 可复现性：为什么 Pillow 被精确锁版本

示例图用 `NotoSansSC-VF.ttf`（**可变字体**）绘制。
可变字体的「默认实例」由渲染库挑，不同 Pillow 版本挑的不一样
（本机 9.5.0 挑 `Thin` 极细体）⇒ 同一份代码渲染出的字形不同 ⇒ 示例图 md5 对不上。

⇒ `requirements.txt` 里 `Pillow==9.5.0` 是**精确锁**，不是 `>=`。
⇒ 详见 `references/铁律.md` 第 34 条。
